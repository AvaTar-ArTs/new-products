# Product Lifecycle

Each catalog entry moves through explicit stages:

1. `idea` — problem and buyer are stated.
2. `evidence` — local assets, competitor evidence, and user pain are recorded.
3. `scored` — opportunity score and launch order are recorded.
4. `spec` — sellable surface, pricing, and acceptance criteria exist.
5. `mvp` — a runnable version exists with tests and a demo path.
6. `launch` — distribution assets and support policy are ready.
7. `measure` — installs, activation, retention, sales, and failure reports feed back into the catalog.

No product should be marked `launch` solely because code runs. It also needs a
README, license, install path, upgrade path, support boundary, privacy note,
demo evidence, and a reproducible release artifact.
